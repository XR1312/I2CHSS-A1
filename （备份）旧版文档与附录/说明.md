## 一、本作业选择了什么

- **论文**：Oswald, L. (2024). *More than news! Mapping the deliberative potential of a political online ecosystem with digital trace data.* Humanities and Social Sciences Communications, 11:629. https://doi.org/10.1057/s41599-024-03115-0
- **体验的阅读工具**（第 2 部分）：**Claude Code v2.1.296**（Anthropic 官方 CLI；本次运行的后端模型为 DeepSeek-V4.1-Flash），于本机实测，2026 年 10 月 10 日。
- **复现对象**（第 3 部分）：论文的**潜类别分析（LCA）网站分类**——69 个政治相关域名 × 15 条二值"审议潜能"标准 → 3 类网站结构（主流枢纽 / 优质信息提供者 / 小众论坛）。

## 二、第 2 部分是怎么做的（为什么不是"随便问几句"）

为了让评估结论站得住，实测被设计成 **5 个可对照的条件**，以区分"失败的不同性质"（幻觉 / 输入缺失 / 论文本身有错）：

| 运行 | 条件 | 用途 |
| --- | --- | --- |
| Run A | 有正文 + 补充材料 | 详细摘要（7 个维度），测覆盖与遗漏 |
| Run B | 同上 | 8 个具体数字问答，要求标出处 |
| Run C | 同上 | 7 个前提真假混合的陷阱题，测是否被带偏 |
| Run D1 | **隔离环境，只有正文** | 测**幻觉率**：答案全在补充材料里，看它是否凭记忆编造 |
| Run D2 | 与 D1 同一组问题，**提供补充材料** | D1 的对照，唯一变量是补充材料是否可得 |

**核心实测发现**（详见评估报告）：

1. **没有观察到幻觉**。Run D1 在信息缺失时 6 题全部如实弃答，并自证"正文中 BIC 一词出现 0 次"（经核验属实）；Run D2 在 5 张拟合表上的 50 余个数值逐格核对全部正确。
2. **错误是"传染"的**。论文正文的一处笔误（把三类网站写成 34/20/25，合计 79，与论文自述的 69 个域名矛盾；表 C1 与混合比例都支持 34/15/20），在 5 次运行中污染了 3 次输出；其中 Run C 甚至用这个错误数字**推翻了正确的前提**。
3. **算术自检是分界线**。只有做了"把数字加一遍、比例算一遍"的那次运行（D2）得到了正确结论。
4. **审计深度取决于提问措辞**。泛问"作者如何选择类别数"得到的是复述；明确要求"核对 Table C2 的 BIC 数值"时，工具就发现了论文的实质性问题（BIC 最小值在 2 类解，作者却选 3 类解）。

论文的 Data availability 声明称"all R scripts and publicly available data … OSF https://osf.io/atj5u/"。2026-10-10 的第一次核查只请求了 `osfstorage` 一个存储提供者：

```
GET https://api.osf.io/v2/nodes/atj5u/files/osfstorage/   ->  HTTP 200，1 个文件

并据此错误地得出"仓库里只有补充材料 PDF"。**OSF 节点的文件系统可以挂载多个存储提供者（provider），osfstorage 只是其中之一。** 该节点还挂了一个 `github` 提供者（与 GitHub 仓库双向链接），论文承诺的 R 脚本与公开数据全在那里。正确的做法是先列提供者再逐个列举：

```
GET https://api.osf.io/v2/nodes/atj5u/files/              ->  2 个提供者
    osfstorage  (kind=folder)   ->  supplement.pdf

## 四、复现实跑结果（用公开数据 + 官方脚本的等价实现）

为了确认数据真的够用，我用 Python（numpy）按其脚本的 EM 过程（`nrep` 随机起点、`maxiter=3000`、`tol=1e-5`、`set.seed(9876)`、`npar = K·15 + (K−1)`）独立重跑了 K=1–10 的模型，逐格复核补充材料表 C2，结果见 `附录_代码与数据/repro_report.txt`：

- **数据核对**：点击量合计 493,714（与正文一致）；69 个域名的点击量与表 C1 **逐站一致（69/69）**；类别规模 15/20/34，混合比例 21.7/29.0/49.3%，与正文的 22/29/49% 相符。**由此可确认正文"34 … 20 … and 25 websites"是把 15 写成 25 的笔误**——这一点现在是证据，不再是推测。
- **拟合指标**：K=1–4 的 logLik / Df / BIC / aBIC / CAIC / Gsq 与表 C2 四舍五入后**逐格相同**；K=3 的 207 个后验概率与数据文件里作者已存的 X1/X2/X3 **最大绝对偏差 0.0001，类别归属 69/69** 一致；两类解 34/35 与表 C3 的 C1/C2 列**完全一致**。
- **四个需要说明的发现**：
  1. 表 C2 中名为"AIC"的那一列其实是 **CAIC**——脚本写作 `data.frame(..., AIC = CAICs, ...)`，而 `CAICs` 等于 `−2ll + npar·(1+log N)`。真正的 AIC 在 K=5 才最小。
  2. **脚本自身的选择规则（取 BIC 最小）会选出 2 类解**，而正文报告的是 3 类解；各准则彼此冲突（BIC 与 CAIC → 2 类，aBIC 一路降到 10 类，真 AIC → 5 类）。
  3. **K≥5 各行的似然是起点依赖的局部极大值**：把随机起点从 30 加到 400，K=6/8/9 的似然分别还能改善 3.7/3.8/4.3。
  4. **`incl_gender`、`incl_age`、`incl_educ` 三列在公开矩阵中取值完全相同**（各 34 个 1，两两 r = 1.000），15 条标准实际只有 13 种互异取值，而自由度仍按 15 条计算。
